Rules and Workflows Audit

How each of Kade's repositories applies the global rules from enjay27/claude-global, how their GitHub workflows compare, and what to keep, change, add or remove.

2026-10-11global rules v2026.10.1111 repositories9 CLAUDE.md · 10 rules files · 8 repo skills · 63 workflows

This page lives in a public repository. It compares process rules and workflows only. Private product details from stella-rain/app are left out on purpose; where a finding touches them, it says so without the detail.

1. Summary

Ten findings, most urgent first. Each one has its action in section 12.

  1. brokenThe star-resonance Project bridge has not worked since 2026-10-09. star-resonance/.github is private, but its CLAUDE.md and the callers' comments call it public. Since resonance-lab #90 and resonance-stream #297 switched to it, resonance-lab's project-sync has failed on all 15 issue events: each run lasts 0 s, starts no job and shows the file path as its name, so GitHub cannot resolve the workflow. Both project-snapshot jobs fail at Check out the bridge script. The Resonance STATUS.md that sessions read is frozen at 2026-10-09 13:18 UTC.
  2. riskstar-resonance auto-merge has none of the guards the other two implementations have. In resonance-stream and resonance-lab, a claude/* PR that edits .github/workflows/ (including auto-merge.yml or the CI it waits for) merges itself once CI is green. It also merges drafts. resonance-lab merges into any base branch, not only main. Both grant contents, pull-requests and actions: write at the top level.
  3. ruleresonance-stream and resonance-lab break the global workflow rule across the board. 14 of their 16 workflows fall short (only the two project-sync callers are clean): 14 lack top-level permissions: {}, 15 checkouts keep credentials (including in the signing workflows release.yml and metadata.yml), 7 steps use dtolnay/rust-toolchain@stable, and 15 jobs have no timeout. Neither repository has the .gitattributes the global rules require.
  4. conflictapp and core say "build on Proposed ADRs"; the global repo-workflow skill says the opposite. The skill says "If the plan says proposed, ask him to accept it first; add no dormant caller". lakehouse matches the skill ("code enters only under an Accepted ADR"). app and core do not, and they name no override.
  5. ruleRepositories without CI are told to turn on GitHub auto-merge. The global rule says cloud sessions turn on GitHub auto-merge unless the repository has its own auto-merge workflow. claude-skills and stage-template have no workflows at all, so auto-merge would merge at once with nothing checked. Neither names an override.
  6. driftDocumentation claims what the code does not do. stella-rain/.github says repo-check.yml is called by core and moderation; nothing calls it. star-resonance/.github says it is public; it is private. resonance-lab's workflow-control skill points at a "Test first" guardrail its CLAUDE.md no longer has.
  7. gapstella-rain/app's main is not re-tested after auto-merges. Merges made with GITHUB_TOKEN start no push run, so godot-ext last ran on main on 10-09. core covers this with a weekly scheduled run of rust.yml. The star-resonance repositories dispatch CI on main after each merge. app has neither.
  8. driftThere are three auto-merge implementations, four sets of ported scripts and two bridge copies. lakehouse's ports of auto_merge_gate.py, branch_cleanup.py, repo_check.py and claude_md_check.py differ from stella-rain's by 61, 52, 30 and 5 lines. Nothing checks the "ported from <commit>" headers.
  9. consistencyOnly 5 of 9 CLAUDE.md files have the "Overrides of global rules" section. app, core, resonance-lab and stage-template have none, so a reader cannot tell "no override" from "forgot to say". lakehouse writes "None.", which is the clearest form.
  10. headroomTwo CLAUDE.md files are at the cap. lakehouse is at 100/100 lines and core at 99/100. The next rule either can add will fail CI.
